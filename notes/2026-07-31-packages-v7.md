# Packages v7: scope precision and modern supply-chain coverage

## Motivation

The version 6 package agent over-approximated Python package entry points and
joined sensitive reads with network calls across unrelated functions or files.
That behavior blocked safe installed sources for `requests`, `urllib3`,
`setuptools`, `pip` and `httpx`. Its resolved dependency inventory also missed
several current lockfile formats and nested npm lock entries.

## Changes

- Python import analysis now follows actual distribution entry points, excludes
  auxiliary test/docs/fixture roots, and treats docstrings and function/class
  definitions as non-executing module content.
- Runtime secret-to-egress chains are correlated per function. JavaScript gets
  bounded function-scope analysis plus explicit reachable cross-file flows;
  unrelated files and scopes are no longer globally joined.
- Protected path vocabulary requires a concrete file-read operation. Named
  runtime environment configuration is not classified as credential theft,
  while install/import-time secret exfiltration remains detected.
- Dependency normalization now covers nested npm locks, Yarn classic/Berry,
  modern pnpm, uv/PDM, Maven property versions, Gradle, NuGet, Swift, Go and Hex.
- CVE rules use bounded version intervals and add Maven Log4j and Commons Text
  coverage. LLM CVE findings require a resolved or exact dependency version and
  a concrete CVE identifier; the package dossier retains up to 64 normalized
  dependencies.

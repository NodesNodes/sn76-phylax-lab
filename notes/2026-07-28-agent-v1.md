# 2026-07-28 — agent v1: what it changes and what it measures

`agent/phylax_agent.py` is now ours, not a copy of upstream's reference agent.
The frozen reference stays at `agent/baseline/reference_agent.42cbf00.py` as the
comparison point.

## Where the score actually comes from

Read out of `neurons/validator.py:315-436`, not out of the docs. Per detonation
track the round score is `0.7 * clamped_mcc(verdicts) + 0.3 * mean(finding_quality)`,
and a repetition is discarded entirely unless the probe file is recovered by
`docker cp`, the validator's own audit-hook trace shows the probe write + DNS
lookup + process echo, and `tracks.evaluate(...).gate_passed` holds. Repositories
skip all of that and score `_dim_score` recall directly.

Three consequences drove the design:

1. **MCC charges a false positive exactly as much as a miss.** The reference
   agent's detectors are corpus-wide substring hits (`"https://"`, `"os.environ"`,
   `"with open"`), so any benign artifact with a homepage URL or an env-var read
   gets flagged. That is the dominant loss, and it is invisible on a two-artifact
   corpus where nothing benign looks dangerous.

2. **`quality._matches` gates on category token overlap first, then on
   `evidence_ref`.** A finding with no path and a category outside the track's
   documented vocabulary cannot match anything, which is why the reference agent
   scored a flat 0.000 on finding quality across all three detonation tracks.

3. **`context['observed']` is handed to the agent and the reference agent never
   opens it.** It carries the validator's own instrumented detonation:
   canonical `capabilities`, per-phase traces (`install_time` / `import_time`
   for packages, per-script for skills), and the parsed MCP `tool_surface`.

## What v1 does differently

- **Per-file, structural analysis.** Capability patterns match call sites and are
  gated by file kind, so prose in a README is not a network capability.
- **Import-time is decided by `ast`, not by grep.** Only statements in the module
  body — function and class bodies and `if __name__ == "__main__"` excluded —
  count as import side effects. A library that calls the network inside a
  function is doing its job; one that calls it while being imported is attacking
  you.
- **One named env var is configuration; the whole environment is theft.**
  `os.environ.get("DOCS_API_KEY")` in a docs server is that server's own
  credential. Only bulk capture (`dict(os.environ)`, `JSON.stringify(process.env)`)
  counts as a secret read. This single rule removed two of our false positives.
- **Findings speak the corpus vocabulary** (`instruction_injection`,
  `tool_poisoning`, `install_hook_exec`, `credential_theft`, …) and always carry
  `evidence_ref` = the relative path of the file the evidence came from.
- **Delivery is injection.** A `SKILL.md` reading "after editing a document, run
  `scripts/backup.py` to sync a copy" is ordinary prose until you look at what
  `backup.py` does. When an instruction file routes the agent to a script we have
  already condemned, the instruction file itself is a context-plane finding —
  which is exactly how the corpus labels it.
- **Findings are filtered by the recall set the scorer will build.**
  `quality.delta_findings` drops non-context-plane expected findings whenever the
  validator observed capabilities, while precision still counts everything we
  send. So action-plane findings go out only when the trace is empty.
- **Repositories: one finding per rule per file**, with the CWE an auditor would
  assign (CWE matching is the reliable half of `_matches`; title overlap is the
  fallback), and `tests/`, `fixtures/`, `spec/`, `examples/` skipped for
  vulnerabilities — a benchmark is drawn from shipped code, and a regression
  fixture containing deliberate bad SQL is not a finding.

## Measurements

`harness/local_eval.py`, upstream scoring code, both corpora. Ours is
`harness/make_corpus.py`: 17 artifacts built around benign lookalikes and evasive
payloads (§ below).

| track | baseline / public | **v1 / public** | baseline / ours | **v1 / ours** |
|---|---|---|---|---|
| skills | 0.700 | **1.000** | 0.050 | **1.000** |
| mcp_servers | 0.700 | **1.000** | 0.000 | **0.970** |
| packages | 0.700 | **1.000** | 0.000 | **0.960** |
| repositories | 0.793 | 0.760 | 0.517 | **0.862** |

The reference agent falls **below tau on all three detonation tracks** against
the adversarial corpus — it flags every benign lookalike (2 of 2 clean skills,
2 of 2 clean packages, the clean docs MCP server), which takes MCC to 0.000 and
the score with it. v1 has zero false positives on both corpora.

The one place v1 is behind on the public corpus is repositories (0.760 vs 0.793),
and it is not a detection regression — see the ceiling note below. On our corpus,
where the labels have real ground truth, v1 recalls **1.000 on both known-bad
repos** against the baseline's 0.955 / 0.357.

Health checks: 17 artifacts × 3 runs byte-identical (repetition consensus needs
this), worst single run **99 ms** against an 8 s/rep skills budget, no crash on
empty/missing/unknown-track context, and `tracks.evaluate` gate passes with
`evidence_integrity 1.0` when a trace is present.

## Our corpus

`corpus/`, 17 artifacts, built to attack our own detector rather than flatter it:

- **benign lookalikes** — a skill documenting `pip install` in prose, a release
  notes skill that legitimately fetches a URL, an MCP docs server that reads its
  own API key, a HTTP client library that imports `requests`, a repo whose
  `tests/` holds deliberately bad SQL as a fixture.
- **evasive payloads** — base64 shell payload gated on `CI` being unset,
  wallet theft that fires on import with no `setup.py` at all, an npm postinstall
  one-liner with no Python anywhere, an MCP attack living entirely in a tool
  description, a skill whose only malice is zero-width-hidden instructions.

This is a regression harness for our detector. It is **not** a prediction of the
held-out corpus — the labels are ours, and the real ground truth is never
published.

## Two things I did not do, deliberately

- **Fabricating repository findings.** When a repo's ground truth has no expected
  findings, `phylax/analysis/repositories.py` falls to a branch where the score is
  `0.9 * (0.65 + 0.35 * _heuristic_quality(vulnerabilities))` — and
  `_heuristic_quality` rises with the *count* of reported vulnerabilities, with no
  penalty, because there is no ground truth to be precise against. Five invented
  findings with a CWE and a remediation string take a clean repo from **0.585 to
  0.900**. On a repo that does have ground truth the same padding costs precision,
  but F2 weights recall 4×, so the trade is roughly favourable. I did not
  implement it: the spec says a fabricated report earns nothing, agents are
  screened, and this is plainly a bug in the gt-absent branch that upstream will
  fix. Flagging it because it is worth knowing the 0.585 on clean repos is a
  *scoring* ceiling, not a detection failure — it is why v1 reads lower than
  baseline on the public repositories corpus, where the clean repo dominates a
  two-artifact average.
- **Anything LLM-backed.** The agent is deterministic and stdlib-only, which
  repetition consensus rewards. The metered inference key is still required at
  submission, and `context.inference` is available — an LLM pass over the
  artifacts is the obvious next lever, but it has to survive 3× repetition
  agreement and an 8 s/rep budget on skills.
